# Changelog

## 1.2.0 - 请求日志本地归档预览

### 已加入

- 请求日志详情新增本地归档缩略图与大图预览；大图支持关闭按钮、点击遮罩、`Esc`、Tab/Shift+Tab 焦点约束与关闭后的焦点恢复。
- 移动端请求详情改为全屏抽屉，并补充展开状态、对话框语义等 ARIA 信息。

### 行为变更

- 请求日志页只会自动加载 `local_image_url`；上游图片 URL 不再作为缩略图、大图或本地加载失败后的备用源，需要查看时由用户显式点击「上游原图」链接。下游图片 URL 仅保留为日志元数据，不参与图片加载。
- 本地归档缺失、关联失效或图片加载失败时统一显示「本地归档不可用」，不会回退请求上游图片。

### 修复

- 为日志请求和大图图片事件增加代次隔离，避免页面切换、连续打开预览或旧请求迟到时覆盖当前内容。
- 离开请求日志页时会中止活动请求，并清理详情抽屉、大图节点、缓存与全局事件监听，避免旧页面继续响应；当前请求返回 401 时统一进入登录状态失效流程。

## 1.1.1 - 后台认证与导航竞态修复

### 修复

- 进入登录界面时立即清理当前页面；后台导航使用代次所有权与 `AbortController`，忽略过期导航的成功、失败和未授权结果，避免旧页面覆盖较新的内容。
- 串行化会改写 Cookie 的登录、初始化与退出请求：登录和初始化会等待进行中的退出，退出会等待进行中的登录，并复用尚未完成的退出请求。
- 避免延迟的退出响应清除新会话、延迟的登录响应在退出后恢复会话，以及多个乱序退出响应覆盖后续登录状态。

## 1.1.0 - 请求日志提供本地归档 URL

### 已加入

- `/admin/api/logs` 新增查询投影字段 `local_image_url`，从仍有效且未软删除的关联图片记录读取本地归档地址；该字段不是数据库列，无需新增迁移。

### 行为变更

- 日志没有图片关联、关联为空或悬空、图片记录已软删除，或本地公开地址为空时，`local_image_url` 返回空字符串。
- 即使下游响应沿用 `IMAGE_RETURN_MODE=upstream_url`，请求日志仍可独立返回已成功保存的本地归档地址；本次调整不改变该兼容模式的既有响应行为。

## 1.0.1 - 图片归档原子保存

### 修复

- 图片归档改为先流式写入最终目录内的隐藏临时文件，完整写入并成功关闭后再通过同目录 `rename` 发布正式文件，避免下载过程中在正式路径暴露半文件。
- 下载取消、响应截断、图片超过 64 MiB、关闭文件或重命名失败时会清理临时文件，并保留原有最多 3 次 GET 尝试及 500ms、1s 退避行为。

### 行为变更

- 发布流程不执行逐文件 `fsync` 或父目录同步，也不进行第二次完整文件拷贝，以减少机械硬盘额外 I/O；该调整不提供断电持久性或文件系统与数据库之间的事务一致性，进程异常退出仍可能残留隐藏临时文件。

## 1.0.0 - 图片返回 URL 本地化

### 行为变更

- 默认图片返回模式改为 `local_url`：上游生成成功后，Nimbus Painting 会下载图片到本地归档，并向下游返回 `PUBLIC_BASE_URL + /images/...` 形式的本地绝对 URL。
- 新增兼容模式 `IMAGE_RETURN_MODE=upstream_url`：下游响应继续使用上游原始 `image_url`，但本地归档仍会尽力执行。
- `PUBLIC_BASE_URL` 现在为启动必填配置，必须是下游可访问的 `http(s)` 绝对地址，可带 path，不允许 query string 或 fragment。
- 默认 `local_url` 模式下，如上游生成成功但本地下载/保存图片重试后仍失败，接口仍返回 HTTP 200，但图片 URL 为空，请求日志记录 `Success=false` 与 `ImageSaveError`。

### 已加入

- 新增环境变量 `IMAGE_RETURN_MODE`，可选值为 `local_url` / `upstream_url`，默认 `local_url`。
- 新增后台设置 `image_download_timeout_seconds`，默认 180 秒，用于控制从上游 `image_url` 下载并保存本地图片的总等待时间。
- 图片下载增加最多 3 次 GET 重试，并使用 500ms、1s 的上下文感知退避；不重试上游绘图请求，避免重复扣点。

## 0.5.5 - 概览页日志按需拉取

### 改进

- `/admin/api/logs` 支持可选 `limit` 参数（1-100，默认 100），调用方可按场景控制返回数量；非法值会回退默认值，保持向后兼容。
- 概览页「最近活动」现在仅拉取最近 5 条日志，减少不必要的查询与传输开销。
- 请求日志页继续使用默认 100 条列表，现有展示与接口行为不变。

## 0.5.4 - 模型使用统计改为服务端全量聚合

### 修复

- 修正概览页「模型使用统计」只基于最近 100 条日志计算、却以全量任务数作为百分比分母的问题；请求量超过 100 后，展示次数和占比可能偏低且合计不一致。
- 统计逻辑改为服务端基于完整记录聚合，并通过 `/admin/api/monitoring/summary` 的 `model_usage` 字段返回，确保次数、成功数与占比使用同一数据口径。

### 改进

- 模型分组优先使用请求时记录的上游模型名，名称缺失时回退到 `sd{index}`，降低模型索引复用或目录变更对历史统计的影响。
- 前端概览页直接消费服务端统计结果，不再在浏览器端重复推导模型使用数据。
- 新增测试覆盖模型分组、合并、排序、空名回退和成功数统计等关键场景。

## 0.5.3 - 模型目录边界梳理

- 补充测试锁定下游代理模型列表与后台模型目录的边界，防止后续回归。

### 改进

## 0.5.1 - 模型目录配置修复

### 修复

- 修复 `/admin/api/models` 可保存空模型目录或无可用图片模型目录的问题，避免默认生图链路在配置保存后失效。
- 修复默认模型被删除或禁用后 fallback 可能仍指向无效模型的问题；保存目录前会先计算并修复 `default_model_index`。
- 模型目录保存时会规范化 `id`、`name`、`type` 的首尾空白。

### 改进

- 新增 `config/upstream_models.example.json`，让内置模型目录 schema 和默认内容在仓库中可见。
- README 补充模型目录运行文件、示例文件、Docker/source 默认路径和 WebUI 保存逻辑说明。
- 模型目录无变化保存时跳过落盘，减少机械硬盘 HDD 上不必要的临时文件写入、fsync 和 rename；有变化时仍保留原子写入策略。

### 注意事项

- Docker 部署的真实运行文件仍是宿主机 `./config/upstream_models.json` 对应容器内 `/app/config/upstream_models.json`。
- `config/upstream_models.example.json` 仅作示例，不会被服务自动读取或覆盖。
- 已通过 `go test ./...`、`node --check`、`go build ./cmd/server` 和 race test 验证。

## 0.5.0 - 可配置上游模型目录

### 已加入

- 新增文件驱动的上游模型能力目录，默认持久化到 `MODEL_CATALOG_PATH` 指定的 JSON 文件。
- 管理后台新增「模型目录」页面，可增删改模型索引、ID、本地显示名、类型、启用状态和特殊参数规则。
- 新增 `/admin/api/models` 管理接口，用于读取和保存当前模型目录。

### 改进

- 图片生成链路、`/v1/models`、默认模型校验和特殊模型参数兼容均改为读取可配置目录。
- 自然语言文生图类模型的强制步数与是否追加默认正面提示词改为目录规则控制。
- Docker 配置新增 `MODEL_CATALOG_PATH`，模型目录随 `/app/config` 挂载持久化。

### 注意事项

- 本地模型目录只影响未来请求、当前 UI 展示和请求前兼容规则。
- 请求日志、图片记录和统计中的实际模型名仍以上游响应体 `model_name` 为准，不会由本地目录名称反向改写。
- 已通过 `go test ./...`、`node --check` 和 `go build ./cmd/server` 验证。

## 0.4.0 - 上游模型目录与兼容性更新

### 已加入

- 新增集中式上游模型目录，用于统一维护内置模型索引、模型 ID、模型类型和可用状态。
- `/v1/models` 增加返回内置上游模型元数据，便于调用方识别当前服务可用的图片模型与暂不可用模型。
- 新增基于模型目录的图片生成模型校验，避免将不支持或暂不可用的模型请求继续转发到上游。

### 改进

- 将旧的模型索引硬编码范围校验调整为目录驱动校验，后续上游模型列表更新时优先维护集中目录。
- 更新内置上游模型目录至当前上游数据版本，并保留暂不支持的视频模型占位与禁用状态。
- 默认模型配置现在会校验是否为可用图片模型；如历史配置不可用，运行时会回退到安全默认模型。
- 对自然语言文生图类模型增加专门参数兼容处理：固定使用推荐步数，并避免附加默认质量提示词。

### 修复

- 修复旧逻辑中某个图片模型索引被误判为仅编辑模型的问题。
- 修复模型列表更新后旧的 `0-13` 范围限制导致新增图片模型无法使用的问题。
- 避免视频类或暂不可用模型被误用于图片生成链路。

### 注意事项

- 上游模型索引复用仍是后续需要重点处理的风险点；相关分析已写入被忽略的开发文档目录。
- 已通过 `go test ./...` 验证。

## 0.1.0 - 初始框架版

### 已加入

- Go 单体 HTTP 服务。
- OpenAI 兼容接口：`/v1/models`、`/v1/chat/completions`。
- 对 NewAPI 只暴露 `sd-generate` 和 `sd-edit`。
- `sd0` 到 `sd13` 支持普通生图，`sd14` 作为编辑模型保留但暂不实现。
- Prompt 参数解析：`sdX`、`宽*高`、`--seed`、`--steps`、`--cfg`。
- 未指定 seed 时由本服务本地生成随机 seed。
- 上游 `Authorization` 仅透传，不保存。
- 图片下载保存到本地，并通过 `/images/...` 访问。
- WebUI：首次初始化密码、登录、基础设置、提示词组、请求日志、图片管理。
- SQLite WAL 和 MariaDB 支持。
- Dockerfile、docker-compose、`.env.example`。

### 暂未加入

- 真正的图片编辑链路。
- 真实进度流式输出。
- 图片批量打包下载。
- MariaDB / SQLite 之间的数据迁移。
- PostgreSQL 实现。
